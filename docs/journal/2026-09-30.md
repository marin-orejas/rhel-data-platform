# 2026-09-30: Persistent journal

## What I did
- Made the journal persistent on db1, db2 and the NUC. A drop-in `/etc/systemd/journald.conf.d/50-persistent-storage.conf` sets `Storage=persistent` in the `[Journal]` section.
- Restarted `systemd-journald` and moved the logs from `/run/log/journal` to `/var/log/journal` with `journalctl --flush`.
- Set the right group and ACLs on `/var/log/journal` with `systemd-tmpfiles --create --prefix /var/log/journal`.

## What broke and how I fixed it
- `/etc/systemd/journald.conf` does not exist on RHEL 10. The defaults are in `/usr/lib/systemd/journald.conf`. My changes go in a drop-in under `/etc/systemd/journald.conf.d/`, and I had to create that directory.
- The section is `[Journal]`, not `[Journald]`. systemd does not stop on a wrong section name or a typo. It only logs a warning, so I check `journalctl -u systemd-journald` after a change.
- The unit is `systemd-journald`, not `journald`. `systemctl list-units '*journal*'` shows the real names.
- After the restart, journald still wrote to `/run/log/journal` ("Runtime Journal"). It moves to `/var/log/journal` only after a flush request: `journalctl --flush` by hand, or `systemd-journal-flush.service` at boot.
- After the flush, `journalctl` without sudo showed `-- No entries --` and no warning. journald had created `/var/log/journal` as `root:root`, without the `systemd-journal` group and the ACL for `wheel`, so my user could read only its own user journal. The rules for these permissions are in `/usr/lib/tmpfiles.d/`, and `systemd-tmpfiles --create --prefix /var/log/journal` applies them without a reboot.
- `dnf install getfacl` finds nothing, because the package is called `acl`. `dnf provides getfacl` shows which package has a command.
- On the NUC the flush logged "Realtime clock jumped backwards ... rotating". At boot, chronyd had stepped the clock back by 1.2 s, so the old entries were not in time order. journald only started a new journal file, and nothing was lost.

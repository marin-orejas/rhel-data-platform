# 2026-11-07: Standby and backup roles, restore test

I wanted the rest of db1 and db2 under Ansible: the NFS share, pgBackRest and the standby. Three roles own them now. The playbook rebuilt the standby on db2 from an empty data directory in 22.9 s, and a restore test of the newest backup takes 18.1 s and gives the same data as the standby. Both backup failures I chased were outside pgBackRest: db1 was off on the night of the missed diff, and on 2026-11-01 the share was not mounted yet.

## What I did
- Put the NFS export, autofs and the SELinux module under a new role `nfs`. The dry run wanted only to copy the `.te` file.
- Role `pgbackrest` on both hosts, from the PGDG repo and key to the units. The timers run only on db1 (`pgbackrest_timers`).
- The role `postgresql` creates `replicator` and the slot on the primary, and runs `pg_basebackup` on an empty db2.
- Moved db2's data directory aside and ran the playbook. 22.9 s in all, `streaming` about 19 s after the start, same data on both.
- `restore-test.yml` restores the newest backup on db2 on port 5434, compares it with the standby and removes it.
- The copy picked timeline 6. With `--archive-mode=off` none of it reached the archive: no `00000006.history`.
- Ran a full by hand before the check: `20261107-203057F` in 12.9 s, and expire removed the oldest full.
- Added check 23 with 35 checks. One extra line in `pgdg-common.repo` on db2 gave one FAIL, and the role took it out.
- Rebooted both hosts. Checks 23, 22, 10, 14 and 15 pass.

## What broke
- **`journalctl -u pgbackrest@diff.service` was empty for the night of 2026-10-27.** db1 was off from 20:25 the evening before to 12:43, and the diff timer has no `Persistent=true`, so the missed run left no line. I looked at pgBackRest first, but an empty service journal means the service never started: the timer and the boots come first.
- **The catch-up full of 2026-11-01 failed with `[055]`, `backup.info` missing.** Both VMs had booted together, autofs on db1 logged `hostname lookup for db2 failed`, and `nfs-server` on db2 came up 3 s later. pgBackRest saw only a missing file, so a retry in the unit is planned.
- **`chmod: invalid mode: 'A+user:postgres:rx:allow'` in a dry run, on a task that `creates` would skip.** `become_user: postgres` needs `setfacl` from the package `acl`, and the module runs on the host even to check `creates`. The role installs `acl` now.
- **The first restore test got `the database system is not accepting connections` right after `server started`.** `pg_ctl -w` counts a server in recovery as started. The playbook now retries the read with `until`.

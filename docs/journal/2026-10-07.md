# 2026-10-07: NFS share on db2, autofs on db1, backups on db2

## What I did
- Gave db2 its own tuned profile, `virtual-guest-lab`: `virtual-guest` with `[cpu] drop=boost`, so `tuned-adm verify` passes. Both tuned profiles are now in `tuned/` in the repo.
- Checked that `postgres` (UID 26) and `dba` (GID 2000) have the same IDs on db1 and db2. NFS sends numbers, not names.
- Added a 10 GiB data disk to db2, the same way as on db1: GPT, LVM (VG `data`, LV `backup` 3 GiB), XFS, mounted on `/srv/backup` by UUID. The rest of the VG is kept for the replica in phase 3.
- Set up the NFS server on db2: `nfs-utils`, the export `/srv/backup 192.168.122.11(rw)` in `/etc/exports.d/backup.exports`, `nfs-server` enabled and the firewall service `nfs`. The SELinux booleans `nfs_export_all_ro` and `nfs_export_all_rw` are on by default.
- Mounted the share by hand on db1 with `mount -t nfs` and tested it: `root_squash` stops root, `postgres` can write, and the files have the same owner on both hosts.
- Set up autofs on db1 with an indirect map: `/mnt/db2` → `backup` → `db2:/srv/backup`, with `-rw,sync`. The share mounts when a program opens it and unmounts after 5 minutes without use.
- Moved the backups to db2. In `pg-backup.service` only the `ExecStart=` path changed, plus `Wants=` and `After=autofs.service`. Ran a backup and restored `lab` from the dump on db2. The fingerprint matched.
- Deleted the old local backups on db1.
- Added `checks/10-nfs.sh` and pointed `checks/09-backup.sh` to the new path. Tested with autofs stopped (exactly 3 checks fail) and after a reboot of both hosts.

## What broke and how I fixed it
- I ran `pvcreate` a second time instead of `vgcreate`, so `lvcreate` found no VG `data`. The order is PV, then VG, then LV.
- A new XFS file system has no SELinux label on its root directory, so `/srv/backup` showed `unlabeled_t` after the mount. `restorecon` gave it `var_t`.
- `/etc/exports.d` did not exist before `nfs-utils` was installed, so vim could not save the export file. Only `/etc/exports` is there from the start.
- `dnf provides exportfs` found the package only because `nfs-utils` lists that name. For most commands, `dnf provides '*/name'` is the way.
- Without `nfs-utils` on db1, `mount -t nfs` failed with `NFS: mount program didn't pass remote address`. The message does not say that the `mount.nfs` helper is missing.
- `showmount -e db2` fails from db1 with `RPC: Unable to receive`. That is expected: it uses `rpcbind` and `mountd` from NFSv3, and the firewall lets only NFSv4 through.
- `--permanent` only writes the firewall config, like `systemctl enable`. `--reload` applies it now, like `--now`.
- `ssh db2 stat -c '%U:%G %a' file` lost the quotes: ssh joins the arguments and the shell on db2 splits them again. The whole remote command goes in double quotes.
- `RequiresMountsFor=` does not work for an autofs path, because systemd knows only the mounts from fstab and mount units. The backup service waits for `autofs.service` instead.

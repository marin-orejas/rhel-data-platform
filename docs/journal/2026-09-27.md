# 2026-09-27: NUC install

## What I did
- Booted the NUC from the USB stick and checked the hardware first: the disk is `sda` (Kingston SSD, 111.8 GiB), the wired NIC is `enp85s0`, and `/sys/firmware/efi` exists, so it boots in UEFI mode.
- Wrote `kickstart/nuc-host.ks`: static IP, SSH key login, locked root, SELinux enforcing, and LVM with a separate volume group for VM images.
- Checked it with `ksvalidator -v RHEL10`.
- Filled in the password hash with `sed` into a copy outside the repo and served it from the desktop with `python3 -m http.server`. Started the install with `inst.ks=http://...` from the GRUB menu (`e`).
- After the install: checked the hostname, IP, disk layout, SELinux, firewall and sudo. Everything matches the kickstart.
- Added `Host nuc` to `~/.ssh/config`. Now `ssh nuc` just works.
- Registered the NUC with `subscription-manager` and ran `dnf update` (new kernel, rebooted).
- Checked time sync with `timedatectl` and `chronyc sources`. The clock is synchronized.
- Turned off SSH password login with a drop-in file, `/etc/ssh/sshd_config.d/10-hardening.conf`.
- Changed the user password and made a new hash for the kickstart.
- Cleaned up every copy of the old password hash.
- Set "After Power Failure" to Last State and turned on Secure Boot in the BIOS. After the reboot, checked it with `mokutil --sb-state` and `dmesg`, and tested that password SSH is still denied.

## What broke and how I fixed it
- The firewalld service is called `ssh`, but the systemd unit is `sshd`. Easy to mix up in the kickstart.
- `--ignoremissing` in `%packages` hid a group name that does not exist. I removed it, so the install fails loudly instead.
- SSH to GitHub hung after `ssh-add -D`. The GNOME agent (`gcr-ssh-agent`) started `ssh-add` to ask for the passphrase, but no window appeared and the process was stuck at 100% CPU. Fixed by saving the passphrase in the login keyring with `secret-tool store`. Now both keys unlock when I log in to Fedora.
- SSH still accepted passwords after I wrote the drop-in file. I forgot `systemctl reload sshd`, and the journal showed that sshd never reloaded. Always run `sshd -t` first, then reload, and test from a second terminal.
- Old password hashes were left in places I did not expect:
  - `ksvalidator` leaves a copy of every file it checks in `/tmp`
  - the installer saves the kickstart in `/root/anaconda-ks.cfg` and `/root/original-ks.cfg`
  - I deleted all of them
- `sudo grep ... /root/*.cfg` failed with "No such file or directory". My shell expands `*` before `sudo` runs, and my user cannot read `/root`.
- Secure Boot did not turn on. `mokutil --sb-state` showed "Platform is in Setup Mode", which means the BIOS had no Secure Boot keys. Restoring the factory keys fixed it.

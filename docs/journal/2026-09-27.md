# 2026-09-27: NUC install and KVM host

I installed RHEL 10.2 on the NUC from my own kickstart and made it a KVM host that I reach over SSH and Cockpit. Secure Boot, Wi-Fi with a static IP and the libvirt pool all came back after a reboot. What I did not expect: old copies of the password hash in `/tmp` and `/root`.

Phase 0 · Docs: [NUC host](../architecture/host.md), [Tuning](../architecture/system.md#tuning)

## What I did
- Booted the NUC from the USB stick and checked the hardware: a 111.8 GiB SSD, a wired NIC and UEFI mode.
- Wrote `kickstart/nuc-host.ks`, checked it with `ksvalidator` and installed from it over HTTP (`inst.ks=` in GRUB).
- After the install, everything matched the kickstart. `ssh nuc` works, and the NUC is registered and updated.
- Turned off SSH password login, changed my password and cleaned up every copy of the old hash.
- In the BIOS: "After Power Failure" to Last State, and Secure Boot on.
- Moved the NUC to Wi-Fi with the same static IP, so it needs no cable.
- Made it a KVM host with libvirt and Cockpit. My user runs `virsh` on `qemu:///system` without sudo.
- Rebooted. The pool, the network, tuned and Cockpit came back on their own.

## What broke
- **Old password hashes were left where I did not expect them.** `ksvalidator` keeps a copy in `/tmp`, and the installer saves the kickstart in `/root/anaconda-ks.cfg` and `/root/original-ks.cfg`.
- **SSH still accepted passwords after I wrote the drop-in.** I forgot `systemctl reload sshd`. Now: `sshd -t`, reload, then a test from a second terminal.
- **Secure Boot did not turn on.** `mokutil --sb-state` said "Platform is in Setup Mode": the BIOS had no keys, and restoring the factory keys fixed it.
- **My first libvirt pool was gone after a reboot.** `pool-create-as` makes a temporary pool; `pool-define-as` saves it.

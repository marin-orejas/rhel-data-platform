# 2026-10-06: Backups with pg_dump and a systemd timer

I wanted a nightly backup of db1 from a script I wrote myself. `pg-backup.sh` now runs every night at 02:00 from a systemd timer, and a restore of `lab` gave the same fingerprint: `count(*)` 10000 and `sum(id)` 50005000. The bug I remember: without `pipefail`, a failed dump still looked like a backup.

Phase 1 · Docs: [Nightly dumps](../architecture/backups.md#nightly-dumps), [ADR 0003](../decisions/0003-systemd-timers-for-backups.md) · Runbook: [Restore a database from a nightly dump](../runbooks/restore-a-database-from-a-dump.md) · Checks: [09](../../checks/09-backup.sh)

## What I did
- Created the test database `lab` with 10,000 rows and noted its fingerprint.
- Created `/srv/backup/pgsql` (`postgres:dba`, `2750`), so `dba` can read the backups but not delete them.
- Made a backup by hand first: `pg_dump | gzip`, `pg_dumpall --globals-only` and a `tar` of the config files.
- Wrote `pg-backup.sh` by hand, one part at a time: arguments, a loop over the databases, error handling, old files.
- Tested every branch: no argument, no write permission, no server, a database that refuses connections, old files.
- Restored the dump of `lab` into a new database. The fingerprint matched.
- Brought the repo version into the style of the check scripts and ran all tests again.
- Added `pg-backup.service`, `pg-backup.timer` (every day at 02:00) and `checks/09-backup.sh`.
- Swapped phases 2 and 3 in the roadmap: RHCSA practice now comes before replication.

## What broke
- **A failed `pg_dump` gave exit 0.** Without `set -o pipefail` the pipe returns gzip's status, and gzip packed the empty input into a 20-byte file. It looked like a backup.
- **`[ "$failed" -gt 0]` printed `[: missing ']'`, and the script ended with exit 0 after a failure.** `bash -n` did not catch it; only the failure test did.
- **psql looked for the socket on port 5432.** `sudo -u`, cron and systemd do not read `.bash_profile`, so the script sets `PGPORT` itself.
- **`crontab -r` sits next to `-e` on the keyboard** and deletes the whole crontab without asking.

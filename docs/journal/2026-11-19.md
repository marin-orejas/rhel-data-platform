# 2026-11-19: MetalLB and a Gateway API route

I wanted the app reachable from outside the cluster. MetalLB now gives Traefik `192.168.122.200`, k8s3 answers ARP for it, and an HTTPRoute sends every request to the web pods: `200` from nuc in 0.002 s. Before the network policy for Traefik the same request waited 30 s and got `504`. The NodePort on k8s1 from last time has an answer too: firewalld accepts every DNATed connection before it looks at a port.

## What I did
- Cut the DHCP range of `default` on nuc to `.2`–`.199`, so `.200`–`.209` belong to MetalLB. Installed `helm` 4.2.2.
- The base role opens `7946/tcp` and `7946/udp` on k8s1–k8s3 now, for the MetalLB speakers. Check 25 expects them.
- MetalLB 0.16.2 from its chart. The chart brings FRR-K8s by default, and `frrk8s.enabled: false` left four plain pods.
- A test LoadBalancer got `.200`, and `ip neigh` on nuc showed k8s3's MAC. kubeadm's label keeps k8s1 out of it.
- Read `filter_FORWARD` on k8s1: `ct status dnat accept` comes before the zones, so kube-proxy's NodePorts get in anyway.
- Gateway API v1.6.3 with `--server-side`, then Traefik chart 42.4.1. With no route the Gateway on `.200` gave `404`.
- Added the HTTPRoute `web`: `504` after 30.0 s, because Calico dropped Traefik's SYN. `allow-gateway` made it `200`.
- Check 30 has 20 checks. A wrong `sectionName` failed exactly three, and 25–30 passed after a reboot of all three nodes.

## What broke
- **`kubectl apply` printed `httproute.gateway.networking.k8s.io/web configured` on every run.** Nothing changed: `resourceVersion` stayed the same and `diff -k` was empty. For a custom resource kubectl sends a JSON merge patch, which replaces whole lists, and the API server had filled defaults into them.
- **A `helm install traefik traefik/traefik` went into `default`.** I ran it before the version, `-n` and `-f` were in. `helm uninstall` took the release but left the chart's CRDs, because Helm never deletes `crds/`.
- **The `0` from `ssh nuc "curl … ; echo $?"` was not curl's.** Inside double quotes my own shell expands `$?` before ssh runs, so it printed the desktop's last exit code. `\$?` reaches nuc.

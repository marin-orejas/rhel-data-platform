## What broke and how I fixed it
- Counting per field is one pipeline, for example users per login shell: `cut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn`.
- A umask I set for one user did not work, because an older `umask` line further down in the same `.bash_profile` ran after mine. The last line wins. `su - <user> -c umask` shows the value really in effect.
- sshd reads `/etc/ssh/sshd_config.d/` in name order, and the first value of a setting wins. My file sorted after an existing one, so the old values stayed. `sshd -T` shows the effective values.
- A web page had the wrong SELinux label after a move. Instead of fixing the label, I copied it under another name, so the URL the task named returned 404. `restorecon -v <file>` fixes the label, and the file keeps its name.
- `journalctl -p err` means err and everything more severe, priorities 0 to 3: a lower number is more severe. `-p warning..warning` shows one level only.
- Also closed in these exams: autofs enabled at boot, `cp --parents`, and reading back kernel arguments with `grubby --info`.

# 2026-10-01: Data disk and PostgreSQL on db1

## What I did
- Created `db1-data.qcow2`, a 10 GiB thin qcow2 volume in the `default` pool, and attached it to the running db1 as `vdb` with `virsh attach-disk --subdriver qcow2 --live --config`.
- In db1, created a GPT partition table and one Linux LVM partition with `fdisk`. Then created PV `/dev/vdb1`, VG `data` and LV `pgdata` (5 GiB). The other 5 GiB stay free, so I can practise extending the LV later.
- Made an XFS file system with the label `pgdata`, created `/pgdata` and added it to `/etc/fstab` by file system UUID. Tested the entry with `systemctl daemon-reload`, `mount -a` and `findmnt --verify` before any reboot.
- Rebooted the NUC. libvirt-guests shut down db2 and db1 cleanly. Both VMs came back with `/pgdata` mounted, and all three hosts kept the logs from earlier boots.
- Added `checks/05-storage.sh`. It runs on db1 over SSH (`ssh db1 bash -s < checks/05-storage.sh`) and needs no sudo.
- Installed `postgresql18-server` (18.6) from AppStream. The package brings the vendor unit `postgresql.service`, the `postgresql-setup` tool and the system user `postgres`. After the install the service is neither enabled nor running, and there is no cluster yet.
- Added a local SELinux rule, `/pgdata(/.*)?` → `postgresql_db_t`, and applied it with `restorecon` before any data was written.
- Created `/pgdata/pgsql` (owner `postgres`, mode 700). In a drop-in made with `systemctl edit postgresql`, set `PGDATA=/pgdata/pgsql/data` and `RequiresMountsFor=/pgdata`.
- Created the cluster with `postgresql-setup --initdb`, then enabled and started the service. The server runs in the SELinux domain `postgresql_t` and listens only on localhost.
- Rebooted db1. PostgreSQL started on its own. Added `checks/06-postgres.sh`.

## What broke and how I fixed it
- My first volume was raw, although its name ended in `.qcow2`. The file name does not set the format, `--format` does. I deleted the volume and created it again with `--format qcow2`.
- `attach-disk` needs the format too (`--subdriver qcow2`). Without it, libvirt treats the disk as raw.
- `attach-disk --config` alone changes only the saved config. For a running VM that must see the disk now and after a restart, use `--live --config`.
- The disk names in libvirt are only hints for the guest. The CD-ROM is `sda` in libvirt but `sr0` in db1. Names like `/dev/vdb1` can change, so fstab uses the UUID.
- There are three different UUIDs: the file system UUID, the LV UUID and the PV UUID. fstab needs the file system UUID from `blkid`. Without sudo, `blkid` shows only cached devices and missed the new file system.
- `journalctl -b 1` is the first boot in the journal, not the previous one. The previous boot is `-b -1`.
- The `postgresql` package is only the client, version 16. The server is `postgresql18-server`. Versions 16 and 18 cannot be installed together (both conflict on `postgresql-any`), so I removed the version 16 client first.
- Empty output without an error, twice: `rpm -ql postgresql | grep systemd` (the client package has no unit) and `systemctl show -p RequiresMountFor` (a typo, it needs the `s`). When a filtered command prints nothing, run it without the filter first.
- `semanage fcontext -a` on a path that already has a rule in the policy does not add a rule. It changes the existing one locally ("already defined, modifying instead"). `semanage fcontext --delete` removed only my local change, and `restorecon -Rnv /var/lib/pgsql` printed nothing, so the default labels were still right.
- A new XFS file system starts as `unlabeled_t`. Without a rule, `restorecon` gives it `default_t`, which no confined service may use.
- I copied a value from an example into the drop-in (`PGDATA=en_US.UTF-8`). `systemctl show -p Environment postgresql` showed it before `initdb` could use it. Check the config before the step that uses it.
- `postgresql-setup --initdb` warned that the parent of the data directory is a mount point. PostgreSQL recommends a `postgres`-owned directory between the mount point and the data directory: an upgrade moves `data` to `data-old` in the same parent. I stopped the service, moved the cluster to `/pgdata/pgsql/data` and changed the drop-in. A stopped cluster can be moved, because it does not store its own path.
- Pasting the check script into vim lost the first line and one check, and the script still printed "All checks passed". Compare the number of PASS lines with the number of checks.

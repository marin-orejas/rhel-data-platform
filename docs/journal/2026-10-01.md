# 2026-10-01: Data disk and PostgreSQL on db1

db1 got a second disk for the database, and PostgreSQL 18 now runs from it, starts at boot and does not start without the disk. The mistake I want to remember: I copied a value from an example into the drop-in (`PGDATA=en_US.UTF-8`), and only `systemctl show` caught it before `initdb` used it.

Phase 1 · Docs: [Data disks](../architecture/vms.md#data-disks), [PostgreSQL on db1](../architecture/postgresql.md) · Checks: [05](../../checks/05-storage.sh), [06](../../checks/06-postgres.sh)

## What I did
- Created `db1-data.qcow2`, a 10 GiB thin volume, and attached it to the running db1 with `--live --config`.
- In db1: one GPT partition, then PV, VG `data` and LV `pgdata` (5 GiB). The other 5 GiB stay free for later.
- XFS on `/pgdata`, in fstab by UUID, tested with `mount -a` and `findmnt --verify` before any reboot.
- Rebooted the NUC. Both VMs came back with `/pgdata` mounted. Added `checks/05-storage.sh`.
- Installed `postgresql18-server` (18.6). After the install nothing runs: no cluster, and the service is not even enabled.
- Labelled `/pgdata` `postgresql_db_t` before any data was written, and set `PGDATA` and `RequiresMountsFor=/pgdata` in a drop-in.
- Created the cluster with `postgresql-setup --initdb` and enabled the service. It came up on its own after a reboot. Added `checks/06-postgres.sh`.

## What broke
- **I copied a value from an example into the drop-in** (`PGDATA=en_US.UTF-8`). `systemctl show -p Environment postgresql` caught it, so now I check the config before the step that uses it.
- **My first volume was raw, although its name ended in `.qcow2`.** The file name does not set the format, `--format` does, and `attach-disk` needs `--subdriver qcow2` too.
- **`postgresql-setup --initdb` warned that the parent of the data directory is a mount point.** An upgrade moves `data` to `data-old` in the same parent, so I moved the cluster to `/pgdata/pgsql/data`.
- **Pasting the check script into vim lost the first line and one check**, and it still printed "All checks passed". I compare the number of PASS lines with the number of checks.

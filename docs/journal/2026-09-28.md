# 2026-09-28: Base VM image

I wanted one base VM image to clone the db VMs from. `rhel-base` now installs from a kickstart over the serial console, always gets `.10`, and its 20 GiB disk uses about 2 GiB on the host. Hash copies again: one in `/tmp` and an old kickstart in the Trash.

Phase 0 · Docs: [Base VM image](../architecture/vms.md#base-vm-image)

## What I did
- Copied the RHEL 10.2 DVD ISO to the NUC and moved it into `/var/lib/libvirt/images/`.
- Added a DHCP reservation: MAC `52:54:00:00:00:10` always gets `192.168.122.10`.
- Wrote `kickstart/rhel-base-vm.ks` from the NUC kickstart: DHCP, root 15 GiB, swap 2 GiB and a serial console.
- Installed the VM with `virt-install --location`, with the whole install on the serial console.
- Added `Host rhel-base` with `ProxyJump nuc`, so `ssh rhel-base` works from the desktop.
- Deleted the hash copies and rebooted the NUC. The VM kept its IP, and it has no autostart on purpose.

## What broke
- **The ISO still had `user_home_t` after the move.** `mv` keeps the SELinux label, and `restorecon -v` changed it to `virt_image_t`.
- **`virt-install` without `mac=` in `--network` gave a random MAC**, so the VM missed the reservation.
- **One typo in `~/.ssh/config` (`IdentifyFile`) broke every SSH connection**, not only that host. `ssh -G <host>` shows the final config without connecting.
- **Hash copies again.** One in `/tmp` from `ksvalidator`, and an old kickstart in the Trash: the file manager only moves files there.

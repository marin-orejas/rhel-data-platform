# 2026-09-28: Base VM image

## What I did
- Copied the RHEL 10.2 DVD ISO to the NUC with `scp`, moved it into `/var/lib/libvirt/images/` with `sudo mv` and fixed its SELinux label.
- Added a DHCP reservation to the libvirt `default` network with `virsh net-update ... --live --config`: MAC `52:54:00:00:00:10` always gets `192.168.122.10`.
- Wrote `kickstart/rhel-base-vm.ks`, starting from the NUC kickstart: DHCP, disk `vda` with `reqpart --add-boot`, VG `rhel` with root 15 GiB and swap 2 GiB, a serial console in the bootloader, and `qemu-guest-agent` and `tuned`.
- Served it from the desktop again and installed the VM with `virt-install --location <ISO>`, UEFI, no graphics and `--extra-args "inst.ks=... console=ttyS0,115200"`. The whole install ran on the serial console.
- Checked from the NUC: the VM got `.10`, and the 20 GiB disk uses only about 2 GiB on the host (thin qcow2).
- Added `Host rhel-base` with `ProxyJump nuc` to `~/.ssh/config`. Now `ssh rhel-base` works from the desktop.
- Checked in the VM: hostname, disk layout, SELinux, firewall and the guest agent. tuned picked the `virtual-guest` profile on its own.
- Deleted every copy of the password hash that the install left behind.
- Shut down the VM, rebooted the NUC and checked that the VM, the reservation and the IP all came back. The base image has no autostart on purpose.

## What broke and how I fixed it
- `mv` keeps the SELinux label. The ISO still had `user_home_t` from my home directory. `restorecon -v` changed it to `virt_image_t`.
- `autopart` and `reqpart` cannot be used together. `reqpart --add-boot` creates only EFI and `/boot`, and I define the rest by hand.
- `reqpart` made `/boot` 2 GiB (the RHEL 10 default), not 1 GiB like on the NUC. Only 420 MiB is left free in the VG.
- `virt-install --location` needs the ISO file, not the directory. Without `mac=` in `--network`, the VM gets a random MAC and misses the reservation.
- `firewall --service=ssh` in a kickstart only adds `ssh`. The zone keeps its defaults (`cockpit`, `dhcpv6-client`).
- `Ctrl+]` does not work on a Croatian keyboard. `Ctrl+5` sends the same character and leaves `virsh console`.
- In `virsh console`, `Ctrl+D` only logs out and the console stays open. Over SSH, `Ctrl+D` closes the connection.
- A typo in `~/.ssh/config` (`IdentifyFile`) is a fatal error that breaks every SSH connection, not only that host. `ssh -G <host>` shows the final config without connecting.
- `ssh -g` is not `ssh -G`. With `-g` it really connected, and the shell output went into `grep`, so it looked stuck.
- Hash copies again: `ksvalidator` left one in `/tmp`, and an old kickstart from yesterday was still in the Trash. Deleting a file in the file manager only moves it there.

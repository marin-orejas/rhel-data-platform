# 2026-11-04: App and read-only roles

I wanted a login for an app and a read-only login for one database, by hand first, then from the role. The role `postgresql` now keeps `app` and `report` on db1, and check 21 passes 19 of 19 after a reboot of both hosts. In the first dry run the task for the logins said `skipping`, not an error: I had named the list wrong, the same slip as yesterday.

Phase 4 · Docs: [Ansible](../architecture/ansible.md), [PostgreSQL](../architecture/postgresql.md) · Checks: [20](../../checks/20-postgresql-templates.sh), [21](../../checks/21-app-roles.sh)

## What I did
- Made `app` and `report` by hand on db1, with passwords from `\password`, and the database `app` with nothing for `PUBLIC`.
- `app` owns the schema `app`. `ALTER DEFAULT PRIVILEGES FOR ROLE app` gives `report` `SELECT` on every new table there.
- From db2, `report` read the new table `orders` with no `GRANT` on it. `INSERT` got `permission denied for table orders`.
- Two `pg_hba.conf` lines let `app` and `report` in from db2, only to `app`. On `lab`, `report` gets `no pg_hba.conf entry`.
- Then as code: `community.postgresql` 3.0.0 on the desktop, `python3-psycopg2` on both hosts, a task file in the role.
- The tasks run only where `pg_is_in_recovery()` is `f`. db2 gets everything through replication and skips them.
- The dry run against my setup by hand gave db1 `ok=22 changed=0`. I took `USAGE` away by hand, and the next run put it back.
- Added `checks/21-app-roles.sh`. Check 20 still counted 12 `pg_hba.conf` rules, but there are 14 since the two new lines.

## What broke
- **`skipping` on `Create the login roles` in the first dry run on db1, with no error.** I had named the list `postgresql_login_rules`, and the default `[]` in the role gave the loop nothing to do. A wrong variable name is never an error in Ansible, so the dry run has to show the task with its items.

# 2026-11-14: Kubernetes nodes

I wanted three nodes ready for kubeadm: clones of `rhel-base` with the base role, no swap, CRI-O and the Kubernetes 1.36 packages. `kubeadm init phase preflight` on k8s1 now ends with exit 0, and check 25 passes all 87 checks after a reboot. The swap took more than `swapoff`: the LV was also named in the kernel arguments of four boot entries, one of them a rescue entry with the machine ID of `rhel-base`.

## What I did
- Cloned k8s1 to k8s3 from `rhel-base`, 2 vCPU and 2.5 GiB each, on `.21` to `.23`. All three run RHEL 10.3.
- The base role runs on a new group `k8s`, with `k8s_control` and `k8s_workers` for each role's ports. Second run `changed=0`.
- On k8s1 by hand: swap off, the fstab line and the LV gone, and `grubby` took `resume=` and `rd.lvm.lv=rhel/swap` out.
- `ip_forward = 1` in `/etc/sysctl.d/k8s.conf`. kubeadm checks only that and the swap, so I added no `modules-load.d` file.
- CRI-O 1.36.8 and kubelet, kubeadm and kubectl 1.36.6 from the upstream repos, the four locked with `dnf versionlock`.
- SELinux stays enforcing, though the kubeadm install page says `setenforce 0`. `crio` runs as `container_runtime_t`.
- Then k8s2 and k8s3 the same way, with exact versions so the three match.
- Check 25 reads the nodes through Ansible as root. With `ip_forward=0` on k8s3 it gave exactly one FAIL.

## What broke
- **After `dnf -y upgrade`, k8s2 and k8s3 still ran `6.12.0-211.7.3.el10_2`.** That is the kernel of `rhel-base`. I had skipped the reboot on both, and the new kernel runs only after one.
- **The kubelet stayed in `activating (auto-restart)` with `open /var/lib/kubelet/config.yaml: no such file or directory`.** Nothing is wrong: `kubeadm init` writes that file, so the kubelet restarts every 10 s until the cluster exists.
- **Preflight warned `the sandbox image "registry.k8s.io/pause:3.10.1" of the container runtime is inconsistent with that used by kubeadm`.** CRI-O picks the pause image and kubeadm only compares. A drop-in in `/etc/crio/crio.conf.d/` sets `3.10.2`, and CRI-O reads it only at start.
- **`virsh console` in the same terminal tab wiped my scrollback.** The commands of the clone steps were gone before I copied them. I don't know why yet. The safe way is a second tab for the console.

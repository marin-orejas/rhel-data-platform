# 2026-11-01: Data disks and PostgreSQL as code

I wanted the data disks and PostgreSQL on db1 and db2 described as code. The system role `storage` took over the disks I built by hand with `changed=0`. The system role `postgresql` keeps its data directory at `/var/lib/pgsql/data`, so I wrote my own role, and check 19 passes 26 of 26 after a reboot of both hosts.

Phase 4 · Docs: [Ansible](../architecture/ansible.md), [PostgreSQL](../architecture/postgresql.md), [VMs](../architecture/vms.md) · Checks: [19](../../checks/19-storage-postgresql.sh)

## What I did
- Installed `linux-system-roles` 2.5.0 on the desktop. The roles need their full name, because `roles_path = roles`.
- Read the disks on db1 and db2 with `lsblk`, `/etc/fstab` and the LVM tools, and wrote them as `storage_pools` in `host_vars`.
- The storage role needs `python3-blivet` on the hosts even for `--check`, so I installed it with an ad hoc `dnf` first.
- `--check --diff`, then a real run of `storage.yml`: `changed=0` on both hosts, and no line in `/etc/fstab` changed.
- Ran the system role `postgresql` with `--check` on db1 only: `changed=2 failed=1`, and nothing changed on db1.
- Wrote my own role `postgresql`: packages, a stop when `/pgdata` is not mounted, the drop-in, `.bash_profile`, `initdb` only without `PG_VERSION`.
- Dry run, run, run again: db1 `changed=0` each time, db2 `changed=1` for `postgresql18-contrib`, then `changed=0`. No restart on either host.
- Added `checks/19-storage-postgresql.sh`. I removed contrib on db2 by hand, two checks failed, and the playbook put it back.

## What broke
- **`Destination /var/lib/pgsql/data/postgresql.conf does not exist !`** The system role looks for its own data directory, not the running cluster, so on the primary it wanted to run `postgresql-setup --initdb`. The dry run on one host showed it before anything changed.
- **`No package postgresql_packages available.`** I wrote `name: postgresql_packages` without `{{ }}`, so `dnf` looked for a package with that name.

# 2026-10-31: A base role for db1 and db2

I wanted one role that keeps the system settings of db1 and db2 the same. The role `base` now holds the users, sudo, SSH, the firewall, SELinux, time sync, tuned and the journal, and check 18 passes 28 of 28 after a reboot of both hosts. A dry run would have missed a tuned profile I changed by hand, because `command` is skipped in check mode.

Phase 4 · Docs: [Ansible](../architecture/ansible.md), [System settings](../architecture/system.md) · Checks: [10](../../checks/10-nfs.sh), [18](../../checks/18-base-role.sh)

## What I did
- Made the role `base` with `roles_path = roles`. Users and sudo gave `changed=0` on the first run, so the role matched my work by hand.
- Installed `ansible.posix` 2.2.1 and `community.general` 12.6.0 from Fedora for the firewall and SELinux modules.
- Put the firewall and SELinux values in `group_vars/db.yml` and db2's `nfs` in its own `host_vars` list. Again `changed=0`.
- Wrote the SSH drop-in `10-hardening.conf` with a reload handler: `changed=2`, then `changed=0`. A login with only a password was refused.
- Moved `postgresql-guest` into the role and put it on db2 too, which had `virtual-guest-lab`. db2 gave `changed=5`, then `changed=0`.
- Added chrony and the persistent journal drop-in. Both were already set by hand, so nothing changed.
- Added `checks/18-base-role.sh`, which reads the live settings (`sshd -T`, `firewall-cmd`, `tuned-adm verify`) through Ansible.
- Switched db2 to `virtual-guest` by hand. Checks 17 and 18 each failed one check, and the next run switched it back.

## What broke
- **`--check` showed `changed=0 skipped=1` with the wrong tuned profile on db2, the same as a clean run.** `command` does not run in check mode, so the switch task was skipped either way. The read task now reports the drift with `changed_when`, and the switch runs `when: base_tuned_active is changed`.
- **`YAML parsing failed: Colons in unquoted values must be followed by a non-space character.`** The `when:` line had `"Current active profile: "` inside an unquoted value. Quoting the whole condition fixed it, and nothing ran on the hosts because Ansible parses all files first.
- **Check 10 failed `no backups left on the root disk of db1`.** An empty `/srv/backup` had stayed on db1 since 2026-10-26, when I made the pgBackRest repo directory there first and removed only `pgbackrest/`. `rmdir /srv/backup` fixed it.

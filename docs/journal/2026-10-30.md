# 2026-10-30: Ansible from the desktop and the first playbook

I wanted to change db1 and db2 from the desktop instead of logging in to each one. Now a user `ansible` with its own key and sudo exists on both hosts, and the first playbook gave `changed=1` on its first run and `changed=0` on the second. A one-letter hand edit of a file on db2 showed up in the next `--check` run.

Phase 4 · Docs: [Ansible](../architecture/ansible.md) · Checks: [17](../../checks/17-ansible.sh)

## What I did
- Installed `ansible-core` 2.20.7 from the Fedora repos on the desktop, no extra collections.
- Made a user `ansible` (UID and GID 1500) on db1 and db2 with its own key and `NOPASSWD` sudo.
- Put `ansible.cfg` and the inventory in `ansible/`. `ansible all -m ping` gave `pong`, and `-b` with `whoami` gave `root`.
- Set `ansible_python_interpreter=/usr/bin/python3` for the group, which silenced the warning about `/usr/bin/python3.12`.
- Installed vim with `dnf` and expected `CHANGED` on db2. It said `ok` on both: db2 had `vim-enhanced` since 2026-10-25.
- Wrote `/etc/motd.d/ansible` with `copy` three times: changed, no change, then only db2 after I edited it by hand.
- Moved the three things into `playbooks/base.yml`. `--check --diff` showed the new line and changed nothing on the hosts.
- Added `checks/17-ansible.sh`, which runs on the desktop. 12 of 12 pass after a reboot of both hosts.

## What broke
- **The first run of check 17 failed all six ad hoc checks, but the playbook check passed.** With `--ssh-extra-args "-o BatchMode=yes"`, `ansible` took the value for its own `-o` option and printed only `usage:`, which `2>/dev/null` hid (`ansible-playbook` has no `-o`). Written as `--ssh-extra-args=-o BatchMode=yes` it works for both.
